# Run HydroPol2D from Excel

HydroPol2D supports two configuration sources. Excel mode reads model settings
from workbooks. Bypass mode reads the same type of settings from MATLAB files
under `Config/`. Both paths use the same numerical solver.

## Start with the tested example

The repository includes a small V-tilted case for both supported mesh paths:

| Mesh | Workbook | MATLAB launcher |
|---|---|---|
| Regular raster grid | `General_Data_regular.xlsx` | `run_regular_excel.m` |
| Voronoi UGRID mesh | `General_Data_voronoi.xlsx` | `run_voronoi_excel.m` |

Clone HydroPol2D, open MATLAB in the repository directory, and run one command:

```matlab
run('Examples/VTilted_Excel/run_regular_excel.m')
```

or:

```matlab
run('Examples/VTilted_Excel/run_voronoi_excel.m')
```

The complete example is in
[`Examples/VTilted_Excel`](https://github.com/marcusnobrega-eng/HydroPol2D/tree/integration/performance-modernization-2026-09/Examples/VTilted_Excel).

## Files required by Excel mode

Keep the main `General_Data*.xlsx` workbook and its companion workbooks in one
directory:

- `LULC_parameters.xlsx`
- `SOIL_parameters.xlsx`
- the active forcing workbook, such as `Rainfall_Intensity_Data.xlsx`
- optional inflow, stage, reservoir, ET, or water-quality workbooks only when
  their corresponding flags are enabled

Raster paths in `General_Data` can be absolute or relative. Relative paths are
resolved from the directory containing the selected main workbook.

## Regular mesh

Set `flag_voronoi = 0`. The regular path reads the DEM, land-cover raster, and
soil raster, then builds the structured computational grid used by the main
MATLAB solver.

## Voronoi mesh

Set `flag_voronoi = 1` and fill `Voronoi case file` with a prepared case MAT
file. That case references the UGRID mesh and raster-overlap files generated by
HydroBathyDEM.

The mesh settings in `General_Data` must match the metadata stored in the UGRID
file. HydroPol2D checks background width, minimum width, adjacent-size ratio,
urban width, transition buffer, and unresolved-river policy before simulation.
This prevents a workbook from silently running a different mesh than the one
the user selected.

Excel selects a prepared Voronoi mesh. It does not generate or modify the mesh
during a model run. The current MATLAB Voronoi runner is CPU-only.

## Select any workbook without editing the launcher

Set the input and output paths in MATLAB, then run the normal launcher:

```matlab
setenv('HYDROPOL_RUN_MODE','excel')
setenv('HYDROPOL_INPUT_EXCEL_FILE','/absolute/path/to/General_Data.xlsx')
setenv('HYDROPOL_EXPORT_ROOT_DIR','/absolute/path/to/Outputs/my_run')
setenv('HYDROPOL_SKIP_POSTPROCESS','')
run('HydroPol2D_V115.m')
```

Set `HYDROPOL_SKIP_POSTPROCESS` to `1` for a solver-only diagnostic run. Leave
it empty for the normal full run.

## Configure with MATLAB files instead

For scripted studies, ensembles, or configuration tracked line by line in Git,
use bypass mode:

1. Set `run_mode = 'bypass'` in `HydroPol2D_V115.m`.
2. Set process and numerical controls in `Config/input_data_bypass_script.m`.
3. Set raster and forcing paths in `Config/input_paths_bypass.m`.
4. Run `HydroPol2D_V115.m`.

Use Excel mode when a workbook is the most convenient project record. Use
bypass mode when the configuration should be generated or reviewed as code.
